# Embedded programs

An EFI program can be stored INSIDE the BinBoot file, so the loader needs
nothing else on the disk to start it. Programs are looked up per architecture
in `blobs/<arch>/`.

The `blobs/` directory is not part of the sources. Create the folder for the
architecture you build for, in the top directory of BinBoot:

```
mkdir -p blobs/x86_64      # for arch=x86_64 (and arch=native on x86_64)
mkdir -p blobs/ia32        # for arch=ia32
mkdir -p blobs/aarch64     # for arch=aarch64
```

(`make` also creates `blobs/<arch>/` by itself when it builds, to place its
generated `test.efi` there.)

Then:

1. Copy the EFI program into that folder, for example
   `blobs/x86_64/rescue.efi`.
2. Declare it once in `config/config.c`, above the entry list, with
   `BB_EMBED(blob_rescue, "blobs/" BB_ARCH "/rescue.efi");`
3. Use it in an entry with `.image = &blob_rescue`.
4. Rebuild. Changing a file under `blobs/` triggers a rebuild automatically.

Details and a full example: [configuration.md](configuration.md).

`test.efi` in these folders is a small test program generated by `make`; it is
rebuilt on every build and is not part of the sources.

Programs you embed keep their own licenses. A BinBoot file that contains them
is a combined work: check that you may distribute what you put in.
